# 03 - 技术博客与分享

## 学习目标
- 通过输出倒逼深度学习（费曼学习法）
- 打造个人技术品牌与影响力
- 为求职/晋升积累硬素材

## 核心理念
> **能讲清楚才是真懂**
> **最好的学习方式是教会别人**

## 博客写作
### 博客选题
- **源码解析系列**（最容易出深度）
- **踩坑系列**（最有共鸣）
- **架构设计系列**（最有价值）
- **面试深度解析系列**（最多流量）
- **技术对比系列**（最易传播）

### 博客结构（金字塔）
```
1. 引子：为什么要读（场景/痛点）
2. 核心结论：一句话总结（先说结论）
3. 详细展开：
   - 原理分析（图 + 源码）
   - 代码示例
   - 对比/替代方案
4. 实战案例：我在项目中如何用
5. 延伸思考：背后的设计哲学
6. 参考资料
```

### 写作原则
- **有图**：流程图/架构图/时序图胜过千言万语
- **有代码**：可运行的Demo
- **有源码**：引用关键源码片段
- **有对比**：和其他方案的对比
- **有思考**：不只是 What，更有 Why 和 How

## 主要发布平台
| 平台 | 特点 | 适合内容 |
|------|------|---------|
| **掘金** | 程序员聚集，流量大 | 深度技术文 |
| **知乎** | 长回答+专栏 | 观点+深度 |
| **InfoQ** | 权威、质量要求高 | 架构/趋势 |
| **公众号** | 私域流量 | 系列文章 |
| **个人博客** | 完全掌控 | 沉淀资产 |
| **GitHub Pages** | 与开源结合 | 项目文档 |
| **Medium / Dev.to** | 英文圈 | 国际影响力 |

## 技术分享
### 分享类型
- **团队内技术分享**（周/月）
- **公司级技术大会**（季度）
- **行业技术大会**（QCon / ArchSummit / GIAC）
- **线上直播**（B站 / 掘金直播）
- **播客**（Tech for Dev / 代码之外）

### 分享准备模板
```
1. 标题：钩子 + 价值
2. 自我介绍（30秒）
3. 背景铺垫（Why）：为什么听众要关心
4. 核心内容：3-5个要点
5. 实战案例：1-2个
6. 总结 & 呼吁行动
7. Q&A
```

### 演讲技巧
- **故事化表达**（不要念 PPT）
- **数据和对比**（有说服力）
- **3的法则**（三个要点最易记）
- **停顿、互动、眼神**

## 开源贡献
### 贡献方式
- **写文档**：最容易上手
- **提 Issue**：发现 Bug、建议
- **提 PR**：修 Bug、加 Feature
- **参与 Review**
- **维护自己的开源项目**

### 推荐切入项目
- Spring 家族
- Apache 顶级项目（Dubbo/RocketMQ/ShardingSphere）
- CNCF 项目
- 国内活跃项目（Sentinel / Nacos / Seata）

## 年度输出目标（推荐）
| 类型 | 数量 |
|------|------|
| 原创博客 | ≥ 12 篇 |
| 技术分享 | ≥ 4 次 |
| 开源 PR | ≥ 2 个 |
| 大会演讲 | ≥ 1 次 |
| 掘金/知乎粉丝 | 增长 1000+ |
