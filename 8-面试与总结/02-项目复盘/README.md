# 02 - 项目复盘

## 学习目标
- 把做过的项目讲成"故事"
- 提炼可迁移的能力与方法论
- 为面试和晋升准备高质量素材

## 复盘维度
每个项目按 **STAR-L 模型** 复盘：
- **S**ituation：项目背景、业务/技术挑战
- **T**ask：你的角色、目标
- **A**ction：关键技术决策、架构设计、落地过程
- **R**esult：可量化的成果（性能/成本/效率/稳定性）
- **L**earning：经验教训、如果重做会怎么改

## 必备的"招牌项目"（建议准备 3-5 个）
每个资深工程师应该有自己的"代表作"，可以从以下维度挑选：

| 类型 | 示例 |
|------|------|
| **高并发** | 秒杀 / 红包 / 抢购 |
| **高可用** | 异地多活 / 同城双活 |
| **海量数据** | 分库分表 / 数据迁移 |
| **架构演进** | 单体→微服务 / 上云 |
| **技术中台** | 消息中台 / 配置中心 / 网关 |
| **基础设施** | 监控平台 / 日志平台 / CI/CD 平台 |
| **性能优化** | JVM 调优 / SQL 优化 / 缓存优化 |
| **疑难杂症** | 线上 OOM / CPU 100% / 数据不一致 |

## 面试亮点提炼
每个项目至少提炼出：
- **1个架构决策**（对比过多个方案）
- **1个深度问题**（排查过程曲折，原理深入）
- **1组量化数据**（性能/成本/稳定性提升）
- **1个创新点**（业内少见的做法）
