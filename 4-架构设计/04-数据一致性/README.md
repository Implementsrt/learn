# 04 - 数据一致性

## 学习目标
- 理解各类分布式事务方案的适用场景
- 能针对业务选择正确的一致性方案
- 掌握最终一致性的落地模式

## 核心知识点
### 事务基础
- ACID（单机）
- BASE（分布式）
- 强一致性 vs 最终一致性

### 分布式事务方案
- **2PC（两阶段提交）**：阻塞、单点故障
- **3PC**：引入超时与预提交
- **TCC（Try-Confirm-Cancel）**：强一致、业务侵入大
- **Saga**：长事务、补偿机制
- **本地消息表**：基于DB + MQ、最终一致
- **事务消息**（RocketMQ）
- **最大努力通知**

### Seata
- AT模式：自动补偿、基于undo_log
- TCC模式
- Saga模式
- XA模式

### 缓存一致性
- **Cache Aside**（先更新DB，再删缓存）
- **延迟双删**
- **Canal订阅binlog**更新缓存
- 缓存与DB不一致场景分析

### 消息一致性
- 消息幂等（业务ID去重）
- 消息顺序（分区有序）
- 消息不丢（生产者确认、Broker刷盘、消费者ACK）
- 消息不重复消费

## 方案选型
| 业务场景 | 推荐方案 |
|---------|---------|
| 跨行转账（强一致） | TCC |
| 订单+库存 | 本地消息表 / 事务消息 |
| 审批流程（长事务） | Saga |
| 短信通知 | 最大努力通知 |
