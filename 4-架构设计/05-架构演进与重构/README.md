# 05 - 架构演进与重构

## 学习目标
- 理解架构演进的内在驱动力
- 掌握安全重构的方法论
- 能主导大型系统的架构升级

## 核心知识点
### 架构演进路径
**单体** → **垂直拆分** → **SOA/ESB** → **微服务** → **服务网格** → **Serverless**

每个阶段的：
- 触发点（业务/技术/组织）
- 收益与代价
- 演进中的坑

### 技术债
- **识别**：SonarQube指标、代码异味
- **度量**：代码坏味道、测试覆盖率、圈复杂度
- **治理**：童子军原则、专项治理、架构看守

### 重构方法论
- **小步快跑**：每次只改一点，保持可发布
- **Strangler Fig 模式**：新旧并行、逐步替换
- **Branch by Abstraction**：通过抽象层隔离变化
- **Feature Toggle**：功能开关灰度
- **双写验证**：数据迁移的标准姿势

### 架构评估
- **ATAM**（架构权衡分析法）
- **Fitness Function**（演进式架构）
- 非功能需求：性能/可用性/扩展性/可维护性/安全

### 架构治理
- 架构评审机制
- 技术雷达（采用/试验/评估/暂缓）
- 架构决策记录（ADR）

## 实战任务
- [ ] 给现有系统画一份完整的 **C4模型图**（Context/Container/Component/Code）
- [ ] 为一次大重构写 **ADR 文档**
- [ ] 用 Strangler Fig 模式规划一次服务拆分
- [ ] 建立团队的 **技术雷达**

## 经典案例
- **阿里** 去IOE
- **美团** 单体→微服务
- **Netflix** 云原生演进
- **eBay** 服务化改造
