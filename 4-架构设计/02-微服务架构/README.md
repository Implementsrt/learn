# 02 - 微服务架构

## 学习目标
- 掌握微服务拆分与治理的方法论
- 理解 DDD 在微服务落地中的价值
- 能主导一次微服务化改造

## 核心知识点
### 微服务 vs 单体
- 何时该拆？何时不该拆？
- 康威定律、团队拓扑
- 微服务的代价（复杂度、运维、数据一致性）

### 服务拆分
- **按业务能力拆**（限界上下文）
- **按子域拆**（核心/支撑/通用）
- **数据库拆分**：每个服务独立数据库
- **拆分反模式**：共享库、分布式单体

### DDD（领域驱动设计）
- **战略设计**：限界上下文、上下文映射、通用语言
- **战术设计**：实体、值对象、聚合、聚合根、领域服务、仓储
- **事件驱动**：领域事件、事件溯源、CQRS
- **六边形架构**：端口与适配器

### 通信方式
- **同步**：REST、gRPC、GraphQL
- **异步**：MQ、事件驱动
- **API Gateway 模式**
- **BFF（Backend For Frontend）**

### 服务治理
- 注册发现、负载均衡、熔断降级
- 配置中心、灰度发布
- **链路追踪**（SkyWalking/Zipkin）
- **日志聚合**（ELK/Loki）
