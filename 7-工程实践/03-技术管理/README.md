# 03 - 技术管理

## 学习目标
- 完成从技术专家到技术领导的转变
- 掌握技术决策与团队培养的方法
- 建立跨团队的技术影响力

## 核心知识点
### 技术选型
- **评估维度**：
  - 成熟度（社区、生产案例）
  - 学习成本、团队熟悉度
  - 性能、可扩展性
  - 维护成本、厂商锁定
  - License 合规
- **技术雷达**：采用 / 试验 / 评估 / 暂缓
- **POC / MVP** 验证
- **架构决策记录（ADR）**

### 技术债治理
- **识别**：代码扫描、架构异味
- **分类**：
  - 故意的 vs 无意的
  - 短期 vs 长期
- **度量**：SonarQube债务、变更成本
- **治理策略**：
  - 童子军原则（每次修改都让代码更干净）
  - 专项治理周
  - 新旧并行逐步替换

### 团队培养
- **新人融入**：Onboarding 清单、Buddy 制度
- **技术成长**：
  - 难度阶梯任务分配
  - 分享文化（内部Tech Talk）
  - 读书会
- **绩效管理**：
  - OKR / KPI
  - 360度反馈
  - 成长路径图（P序列/M序列）
- **Code Review 文化**
- **知识沉淀**：Wiki、ADR、事故复盘

### 项目管理
- **需求管理**：MoSCoW（Must/Should/Could/Won't）
- **估算**：故事点、三点估算
- **风险管理**：识别→评估→应对→监控
- **敏捷实践**：Scrum / Kanban / SAFe
- **依赖协调**：RACI 矩阵

### 跨团队协作
- **非暴力沟通**（NVC）
- **利益相关方管理**
- **对上汇报**：金字塔原理、SCQA
- **冲突管理**

### 架构师软技能
- **技术方案写作**：背景/目标/方案/对比/落地/风险
- **架构评审**：主持 & 参与
- **技术演讲**：故事化表达

## 技术影响力
### 对内
- 推动最佳实践落地
- 建立技术规范
- 培养下一代架构师

### 对外
- 技术博客（掘金/知乎/公众号/InfoQ）
- 开源贡献（PR/Issue/自有项目）
- 技术大会分享（QCon/ArchSummit/GIAC）
- 出书 / 开课

## 实战任务
- [ ] 主导一次技术选型评估（含 ADR）
- [ ] 设计团队的技术成长路径图
- [ ] 组织一次团队级技术分享
- [ ] 完成一次完整的事故复盘（5 Whys / Postmortem）
